## 入门：贪心到底在做什么

想象给一条队伍安排接水顺序，当前只决定“下一个让谁接”。贪心每次依据某条规则作一个局部选择，然后把剩余问题继续交给同一条规则。代码往往短，难点在于证明：这一步不会牺牲后面的最优答案。

```text
先读目标 → 提出规则 → 找反例 → 证明可安全选择 → 实现 → 小规模对拍
                     ↑                          |
                     └──── 发现问题就修改规则 ───┘
```

与上一章对照：递推/递归描述计算组织方式，贪心描述决策策略；贪心也可以循环或递归实现。不能把“有排序”当成“就是正确的贪心”。
<a id="c4"></a>
## K01 贪心算法

### 概念：先当一次“只安排下一步”的队长

假设你有两张兑换券，柜台上的礼物价值分别是 8、3、6，每个礼物都只需要一张券。你会先拿哪个？很自然，先拿价值 8 的，再拿 6 的，最后得到 14。

这就是一次很简单的贪心：**每次只决定下一步，把眼前最划算的选择先做掉。** 不需要列出所有组合，也不需要选完以后再反悔。

但请留意题目中的限制：所有礼物都只花一张券。如果有的花一张、有的花两张，先拿最贵的就未必划算。贪心的名字虽然一样，允许它正确的条件却可能已经消失了。

```text
还剩 2 张券：礼物 [8] [3] [6]
                 ↓ 先取 8
还剩 1 张券：礼物     [3] [6]
                         ↓ 再取 6
最后得到：8 + 6 = 14
```

这里“当前最优”是这一次拿到最贵礼物；“全局最优”是两次拿到的总价值最大。学习贪心时，最重要的一步就是把这两个“最好”区分开。

### 原理：把直觉一步步变成理由

为什么这个例子可以放心取 8？想象有人说他有一个最优方案，却没拿 8。那他一定拿了某个不超过 8 的礼物。把那个礼物换成 8，花掉的券数不变，总价值不会更小。因此，总能找到一个包含 8 的最优方案。

这段话比“8 最大，所以选 8”多做了一件关键的事：它解释了**选 8 不会堵死最优答案**。后面的背包、接水、区间选择，都在用不同方式证明这件事。

### C++ 实现

最简单的安全例子：预算 k 次选择，每个物品成本相同、收益非负，取最大的 k 个。
```cpp
sort(a+1,a+n+1,greater<int>());
int ans=0;
for(int i=1;i<=min(k,n);i++)
    ans+=a[i];
```

### 作用与使用场景

资源调度、可分割资源、某些区间选择、最优合并。若当前选择会改变后续约束，必须证明安全，不能看到最大/最小就套贪心。

## K02 贪心选择性质与最优子结构

### 概念：把两个吓人的术语翻译成人话

“贪心选择性质”和“最优子结构”看起来很抽象，先把它们想成两张通行证。

第一张通行证：**我现在选的这一步，至少有一个最优答案愿意接受。** 这叫贪心选择性质。注意是“至少有一个”，不要求所有最优答案都长得一样。

第二张通行证：**这一步做完以后，剩下的事情仍然可以单独做到最好。** 这叫最优子结构。

还是兑换券的例子：先拿 8 是安全的；拿完以后只剩一张券和两个礼物，这个小问题继续取 6 就行了。大问题的最优答案由“安全的第一步”和“剩余问题的最优答案”接起来。

### 原理：把直觉一步步变成理由

换成比赛安排：你选了一场到 10 点结束的比赛，后面就只需要考虑 10 点开始及之后的比赛。过去已经决定的部分，可以浓缩成一个变量 `last=10`。

```text
已经选好的部分 | last=10 | 尚待考虑的比赛
              不必重算   只问能否接上、还能选几场
```

但不要倒过来想：“能拆成小问题，所以一定能贪心。”0/1 背包也能拆小问题，可是“按单位价值先选”的第一张通行证拿不到。两个条件必须分别检查。

### C++ 实现

实现时让变量准确表示剩余问题，例如区间选择：
```cpp
if(a[i].l>=last)
{
    ans++;
    last=a[i].r;
}
```
last 是已经选择的最后结束时间，之后只考虑可衔接区间。完整实现见 P1803。

### 作用与使用场景

用来搭建证明和检查状态。选完一个区间后，剩余目标仍是最大化后续区间个数；若变成总收益最大，则模型改变，不能直接继承结论。

## K03 反证法与交换论证

### 概念：像整理背包一样，动手交换一个最优解

反证法不是让你凭空想到矛盾。一个常用办法是：**先请来一个号称最优的方案，再试着把它改成你希望的样子。**

比如两种能切开的金属：A 每千克值 6 元，B 每千克值 4 元。背包里装着 B，但外面的 A 还没装完。你不需要一下子重排整个背包，只拿出 1 千克 B，换入 1 千克 A。

```text
交换前：背包里有 1 kg 的 B，价值 4
交换后：同样的位置放 1 kg 的 A，价值 6
重量没变，价值多了 2
```

这个“拿出一点、换进一点”的动作，就是交换论证。若交换前的方案真是最优，怎么还能被改得更好？这就与假设矛盾了。

### 原理：把直觉一步步变成理由

正式写时，设交换重量为 δ，且 δ 不超过“背包里 B 的重量”和“外面 A 的剩余重量”。这样交换一定做得到。

价值变化为 `δ×(6-4)>0`。约束没有被破坏：总重量没变、没有使用超出供应量的物品。目标却严格变好，因此原方案不可能最优。

如果两种物品单位价值一样，交换不增加价值，但也不降低价值。这时应说“存在一个先取 A 的最优解”，不能说“其他顺序一定更差”。写证明时，**可行性、目标变化、相等情况**都要交代。

### C++ 实现

不要用整数除法比较密度，正重量下交叉相乘：
```cpp
bool cmp(node x,node y)
{
    return x.v*y.m>y.v*x.m;
}
```
本题范围下乘积安全；更大范围要另检查溢出。相等时返回 false 符合排序要求，不能写 >=。

### 作用与使用场景

可分割背包、相邻交换排序、树上叶子交换。证明要写明交换后依然可行，以及其他部分的代价为何不变；“显然交换更好”不能代替计算。

## K04 举出反例证伪贪心

### 概念：不要急着证明，先故意找茬

你猜出了一个策略，先别立刻相信它。试着扮演出题人：有没有一组输入，专门让这个策略吃亏？

背包容量 50，三件物品如下：

| 物品 | 重量 | 价值 | 每单位重量价值 |
|---|---:|---:|---:|
| A | 10 | 60 | 6 |
| B | 20 | 100 | 5 |
| C | 30 | 120 | 4 |

如果能切开：拿 A、B，再拿 C 的 20/30，总价值是 240。

如果不能切开：同样按密度拿 A、B 后，只剩 20 容量，C 放不下，价值只有 160。可直接拿 B、C，重量刚好 50，价值却有 220。

规则看起来没变，**“能否切开”这一个条件就决定了它是否安全**。反例的价值不只是说“错了”，更是帮你找到究竟哪里不能交换。

### 原理：把直觉一步步变成理由

数学命题是“对所有合法输入都正确”，反例只需找到其中一个合法输入使结论失败。

所以，跑一千组数据没错，不等于已经证明正确；但只要找出这一组 160 对 220 的合法数据，这个 0/1 背包策略就已经被否定。

想不出反例时，可以先写小规模暴力：让程序枚举每件物品选或不选，计算真正最优值，再与贪心比较。这就是对拍。下面的二进制枚举只是帮你找错的工具，第一次阅读可以先看懂“枚举所有选择”的目的，再回来研究位运算。

### C++ 实现

可用 0/1 子集枚举作为小数据参照：
```cpp
int best=0;
for(int s=0;s<(1LL<<n);s++)
{
    int weight=0,value=0;
    for(int i=0;i<n;i++)
    {
        if((s>>i)&1)
        {
            weight+=m[i];
            value+=v[i];
        }
    }
    if(weight<=t) best=max(best,value);
}
```
仅用于 n<=20 的小规模验证，时间 O(n×2^n)。

### 作用与使用场景

检查“价值最大优先”“最轻优先”“最短区间优先”等直觉。优先找极端值、容量刚好满、并列与长短相互冲突的输入。对拍发现错误有力，对拍未发现错误仍需证明。

## K05 大胆假设，小心求证：相邻交换

### 概念：让接水最快的人先来，会影响谁

有三个人接水分别需要 3、1、2 分钟。先不要写公式，拿纸画一条时间线。

| 顺序 | 第一个人等多久 | 第二个人等多久 | 第三个人等多久 | 总等待 |
|---|---:|---:|---:|---:|
| 3 → 1 → 2 | 0 | 3 | 4 | 7 |
| 1 → 3 → 2 | 0 | 1 | 4 | 5 |
| 1 → 2 → 3 | 0 | 1 | 3 | 4 |

第一行换成第二行时，最后一个人依然在第 4 分钟开始接水，完全没受影响；真正省下的是中间那个人的等待。

这就是相邻交换好用的地方：不需要同时比较所有人的变化，只看被交换的两个人。

### 原理：把直觉一步步变成理由

把相邻两人的时间记为 x、y，并假设 x>y。前面的人用了 P 分钟。

```text
原来：先 x，后 y     等待为 P、P+x
交换：先 y，后 x     等待为 P、P+y
```

两人的总等待减少 `x-y`；后面的人仍然在 `P+x+y` 时刻开始，前面的人也没变。所以每消去一个“长任务排在短任务前”的逆序，答案就会变好。不断交换到没有逆序，就是升序排列。

相同接水时间交换后答案不变；但 P1223 另要求编号小的在前，所以比较器还要比较编号。代码中 `sum+=now` 必须在 `now+=t` 前面：你等的是前面的人接完，不是等自己接完。

### C++ 实现

累计时间 now 是当前人真正等待的时间：
```cpp
int now=0,sum=0;
for(int i=1;i<=n;i++)
{
    sum+=now;
    now+=a[i].t;
}
cout<<fixed<<setprecision(2)<<1.0*sum/n;
```

### 作用与使用场景

单机器、所有任务同时到达、最小化总等待/完成时间的等权模型。有到达时间、不同优先权或多个水龙头时要重新建模。sort O(n log n)，扫描 O(n)；sum 用64位整数。

## K06 数学归纳法证明区间贪心

### 概念：先结束的比赛，给未来留出最大的空地

假设有四场比赛：A 为 [0,3)，B 为 [1,2)，C 为 [2,4)，D 为 [4,5)。

```text
时间  0   1   2   3   4   5
A     [-----------)
B         [---)
C             [-------)
D                     [---)
```

如果选开始最早的 A，之后只能再选 D，共 2 场；选结束最早的 B，却能接上 C、D，共 3 场。

为什么看结束时间？选中的比赛一结束，你才重新获得安排下一场的自由。结束越早，留给后面的时间越多。这个直觉很有用，接下来还要把它变成证明。

### 原理：把直觉一步步变成理由

想象一份已经最优的比赛名单，它的第一场叫 O；我们想选的结束最早比赛叫 G。

把 O 擦掉，换成 G。因为 G 不晚于 O 结束，原名单里 O 后面能接上的比赛，现在仍能接上。数量没有减少，于是我们得到了一份“第一场是 G”的最优名单。

第一步安全之后，把已经占用的时间切掉，余下仍是“最多选多少场”的同类问题，而且区间数变少了。没有区间或只有一个区间时结论显然成立；假设更小的问题都会处理，那么当前问题也会处理。这就是数学归纳法在这里的具体用法。

注意：不是所有短比赛都该先选。例如 [0,3)、[3,6)、[2,4)，最短的 [2,4) 反而挡住另外两场。策略必须是**结束最早**，不能偷换成**长度最短**。

### C++ 实现

按结束时间排序，扫描一次：
```cpp
int last=-1,ans=0;
for(int i=1;i<=n;i++)
{
    if(a[i].l>=last)
    {
        ans++;
        last=a[i].r;
    }
}
```
P1803 时间非负，因此 last=-1 安全；允许负时间时需改初值。

### 作用与使用场景

不带权、要求最多个数的区间选择；端点衔接允许相等。带权区间不能只选结束最早，通常要动态规划。时间 O(n log n)，空间 O(n)；把 >= 写成 > 会漏掉紧接的比赛。

## K07 小根堆与动态维护最小值

### 概念：准备一个“每次自动递来最小数”的盒子

桌上有三堆果子 1、2、9。你先合并 1、2，桌上就变成了 3、9。下一轮要找的，是**现在桌面上**的两个最小数，不是原来列表里的两个数。

小根堆可以想成一个盒子：把数塞进去，每次打开顶部，它都会递来当前最小的数。你不用知道盒子内部的全部顺序。

| 操作 | 像什么 | 要注意什么 |
|---|---|---|
| push(x) | 把 x 放进盒子 | 新合并出来的数也要放回去 |
| top() | 看一眼盒子给出的最小数 | 只看，不删除 |
| pop() | 把顶部那个数拿走 | 本身不返回被拿走的值 |

因此，取走一个数应写成 `x=q.top(); q.pop();`，这两句分工不同。

### 原理：把直觉一步步变成理由

为什么不只在开头 sort 一次？看 1、2、100、101：第一次合成 3 后，下一次应取 3、100。若直接从原数组继续拿 100、101，就漏掉了新出现的 3。

你当然可以每次重新排序，只是浪费时间。小根堆把“插入一个数”和“删掉最小数”都控制在 O(log n)，非常适合这种一边生成新数、一边选最小数的过程。

C++ 的名字有点长，但先把下面整行当作“小根堆的声明”认识即可。默认的 `priority_queue<int>` 给出最大数，末尾的 `greater<int>` 才把它改成最小数。

### C++ 实现

```cpp
priority_queue<int,vector<int>,greater<int>> q;
q.push(3);
q.push(8);
int x=q.top(); // x=3，查看但未删除
q.pop();       // 删除3
```
模板中的 vector<int> 是堆底层存储，greater<int> 使最小值在顶部；默认 priority_queue<int> 则是大根堆。

### 作用与使用场景

反复插入和取最小值的调度、合并、哈夫曼构建。top O(1)，push/pop O(log n)，共 n-1 次合并，所以总 O(n log n)，空间 O(n)。空堆不能 top/pop。

## K08 哈夫曼树的构建与带权路径长度

### 概念：果子为什么会被反复收费

还是 1、2、9 三堆果子。先合 1 和 2 花 3，再合 3 和 9 花 12，总花费 15。

换成先合 2 和 9：先花 11，再花 12，总花费 23。最终都是 12 个果子，为什么费用不同？因为前两堆在后面又被搬了一次。

```text
        12                 1和2：各被搬两次
       /  \
      3    9               9：只被搬一次
     / \
    1   2
```

所以，大重量应该尽量少参与合并，小重量才适合较早合并。把合并过程画成树，原来的每堆果子是叶子；一片叶子到根经过几条边，就会被重复收费几次。

### 原理：把直觉一步步变成理由

“带权路径长度”这个名字可以拆开读：权是果子重量，路径长度是叶子到根的边数，带权就是两者相乘。于是 WPL=1×2+2×2+9×1=15，恰好等于所有合并费用之和。

为什么每次一定能选最小两堆？在一棵最优的满二叉树里，找最深的一对兄弟叶子。把最小的两份重量换到这两个深位置，不会增加费用。原因是对小权 x、大权 y 与浅深 d1<=d2：让小权占深处的费用减去原费用，为 `(x-y)×(d2-d1)<=0`。

这样就能找到一个最优方案，让最小两权成为兄弟。先把它们缩成一个新叶子，权为 x+y，少掉的费用固定为 x+y；剩余继续求最优即可。这个论证才支持代码中不断“取两个最小”，不是因为这个动作看上去便宜。

### C++ 实现

```cpp
int ans=0;
while(q.size()>1)
{
    int x=q.top();
    q.pop();
    int y=q.top();
    q.pop();
    ans+=x+y;
    q.push(x+y);
}
```
只求最小代价无需建树；要生成编码必须保留左右孩子，见例6。

### 作用与使用场景

最优二元合并、文件合并、频次编码。证明依赖非负权、任意两堆可合并且代价等于两权之和；限制相邻合并或改变代价函数后不能照搬。n=1 时无需合并，WPL为0。

## K09 哈夫曼编码与前缀码

### 概念：把常见字放在离出口更近的地方

假设 A、B、C 分别出现 1、2、9 次。每个符号都用两位编码，总共要写 `(1+2+9)×2=24` 位。

如果给 A 编 00、B 编 01、C 编 1，总位数变成 `1×2+2×2+9×1=15`。常出现的 C 只用一位，节省最明显。

但是“短”还不够，必须能读回来。比如 A=0、B=01，就有危险：读到一个 0 时，你不知道它已经是 A，还是 B 的开头。**前缀码**正是排除这种情况：任何一个完整码字，都不能是另一个码字的开头。

### 原理：把直觉一步步变成理由

把符号放到树的叶子上，向左写 0，向右写 1。你读到一个叶子，就已经读完一个符号；接着回根，开始读下一个。叶子下面没有其他符号，因此不会出现“这个符号还有可能只是另一个符号的开头”的犹豫。

例如比特串 `00101`，按 A=00、B=01、C=1，从根走到叶后重新出发，会分成 `00 | 1 | 01`，读出 A、C、B。

根到叶的边数就是码长，所以总位数恰好又是 WPL。上一节的“最少搬运费”，到这里变成“最少编码位数”；同一个数学目标，因此同一棵哈夫曼树可以解决。

编码不一定唯一，左右交换会换出另一个同样好的码表。判断对错应看能否无歧义解码、总位数是否最优，而不是必须逐字等于某一个码表。单符号的空码/0码约定仍按后面的教学接口说明处理。

### C++ 实现

生成过程是上一章学过的树形递归：
```cpp
void dfs(int u,string s)
{
    if(ls[u]==0&&rs[u]==0)
    {
        code[u]=s;
        return;
    }
    dfs(ls[u],s+'0');
    dfs(rs[u],s+'1');
}
```

### 作用与使用场景

已知符号频次的无损编码。左右标记可交换、相等权也可有不同树，所以最优编码未必唯一。单符号模型本章允许空码，需外部给定符号个数；实际格式若强制至少一位可约定0，此时输出长度为频次，不能仍称实际位数为0。

## K10 证明与验证形成闭环

### 概念：给你的贪心安排三次检查

写出一个看起来很顺的策略后，可以让它依次过三关。

第一关，找茬：我能不能找出让它失败的小例子？例如把“能切开”改成“不能切开”，把区间目标从“最多场”改成“总奖金最多”。

第二关，说理：假设有一个最优解不按我的第一步走，我能不能把它交换成我的选择，而且不让答案变差？交换之后，剩余是不是同一类小问题？

第三关，查实现：我说得对，是否也写得对？比较器有没有写反，端点相等能不能接上，计算奖赏是在更新前缀积之前还是之后？

### 原理：把直觉一步步变成理由

这三关各自负责不同的事。

| 检查 | 能发现什么 | 不能替代什么 |
|---|---|---|
| 手造反例 | 策略本身不成立 | 找不到反例不等于正确 |
| 数学证明 | 为什么所有合法输入都满足结论 | 不能保证代码没有笔误 |
| 暴力对拍 | 边界、排序、实现或推理错误 | 小规模通过不等于大规模证明 |

例如合并果子 1、2、9，手算得到 15，可以检查最基本的实现。再让暴力枚举每一步所有两两合并，核对更多小输入。最后仍要回到“最小两叶可放在最深处”的证明，这样才把直觉、推理与代码接在一起。

### C++ 实现

在正式程序外用小数据验证，不把暴力写进大规模解法。例如合并权1、2、9：先合1+2，再合3+9，总代价3+12=15；先合2+9则为11+12=23。代码见完整例5与 verify.py。

### 作用与使用场景

遇到新贪心题先证伪再证明；测试包含n=1、全相等、端点相接、容量不足及单符号。不要用一个样例通过代替正确性证明。

## 例1：部分背包问题（P2240）

[洛谷原题](https://www.luogu.com.cn/problem/P2240)

容量50，(10,60)、(20,100)、(30,120)，先装前两件，再装第三件的20/30，答案240.00。注意真正的可分割条件；不能把整数除法所得密度用于排序。

### 先用一个小例子走一遍

别急着把代码当成背包模板。先想象你正往袋子里倒金粉，袋子还能装多少，就倒多少。

| 本轮物品 | 取走重量 | 增加价值 | 剩余容量 |
|---|---:|---:|---:|
| 10重、60值 | 10 | 60 | 40 |
| 20重、100值 | 20 | 100 | 20 |
| 30重、120值 | 20 | 80 | 0 |

第三轮不需要把整堆搬走，取它的三分之二就行。代码中的 `take=min(t,a[i].m)` 就是问“袋子和这堆金粉，哪一边先用完”；`1.0` 是为了让价值计算保留小数，避免先发生整数截断。排序函数只负责决定先倒哪堆，真正装入多少由循环决定。

### 完整 C++17 程序

```cpp
#include <bits/stdc++.h>
#define int long long
using namespace std;

struct node
{
    int m,v;
}a[105];

bool cmp(node x,node y)
{
    return x.v*y.m>y.v*x.m;
}

signed main()
{
    int n,t;
    cin>>n>>t;
    for(int i=1;i<=n;i++) cin>>a[i].m>>a[i].v;
    sort(a+1,a+n+1,cmp);

    double ans=0;
    for(int i=1;i<=n&&t>0;i++)
    {
        int take=min(t,a[i].m);
        ans+=1.0*take*a[i].v/a[i].m;
        t-=take;
    }

    cout<<fixed<<setprecision(2)<<ans<<'\n';
    return 0;
}
```

## 例2：排队接水（P1223）

[洛谷原题](https://www.luogu.com.cn/problem/P1223)

时间3、1、2，顺序编号2、3、1；等待分别0、1、3，总和4，平均1.33。若先now+=t再sum+=now，就把自己的接水时间也算进去了。

### 先用一个小例子走一遍

把 `now` 想成钟表，而 `sum` 是记录大家等待时间的账本。按1、2、3分钟的顺序接水：

| 轮到谁 | 钟表now | 记到账本的等待时间 | 接完后的钟表 |
|---|---:|---:|---:|
| 接1分钟的人 | 0 | 0 | 1 |
| 接2分钟的人 | 1 | 1 | 3 |
| 接3分钟的人 | 3 | 3 | 6 |

最后钟表是6，账本却是4，二者不是同一个答案。看到程序的两句累加时，试着读成“先记他已经等了多久，再让他开始接水”，就不容易写反。

### 完整 C++17 程序

```cpp
#include <bits/stdc++.h>
#define int long long
using namespace std;

struct node
{
    int t,id;
}a[1005];

bool cmp(node x,node y)
{
    if(x.t!=y.t) return x.t<y.t;
    return x.id<y.id;
}

signed main()
{
    int n;
    cin>>n;
    for(int i=1;i<=n;i++)
    {
        cin>>a[i].t;
        a[i].id=i;
    }
    sort(a+1,a+n+1,cmp);

    int now=0,sum=0;
    for(int i=1;i<=n;i++)
    {
        cout<<a[i].id<<(i==n?'\n':' ');
        sum+=now;
        now+=a[i].t;
    }

    cout<<fixed<<setprecision(2)<<1.0*sum/n<<'\n';
    return 0;
}
```

## 例3：凌乱的yyy（P1803）

[洛谷原题](https://www.luogu.com.cn/problem/P1803)

区间[0,3)、[1,2)、[2,4)、[4,5)，选后三个得3。开始最早的[0,3)会挤掉两个可衔接区间。这里用半开区间理解端点衔接。最短优先也可能错：[0,3)、[3,6)、[2,4)，最短[2,4)只能得1，另两段能得2。

### 先用一个小例子走一遍

`last` 可以想成你日程表上“忙到几点”的标记。选完 B=[1,2)，就把标记放到2：A=[0,3)已经来不及参加，C=[2,4)刚好接得上，再把标记移到4，最后接D。

```text
选 B：last=2
看 A：开始0 < 2，跳过
看 C：开始2 = 2，可以选，last=4
看 D：开始4 = 4，可以选，last=5
```

为什么不用把所有冲突比赛从数组中删除？扫描时判断一次开始时间即可。已经排好的结束时间顺序，保证你依次检查的正是“下一场最早能结束的候选”。

### 完整 C++17 程序

```cpp
#include <bits/stdc++.h>
#define int long long
using namespace std;

struct node
{
    int l,r;
}a[1000005];

bool cmp(node x,node y)
{
    if(x.r!=y.r) return x.r<y.r;
    return x.l<y.l;
}

signed main()
{
    ios::sync_with_stdio(false);
    cin.tie(0);

    int n;
    cin>>n;
    for(int i=1;i<=n;i++) cin>>a[i].l>>a[i].r;
    sort(a+1,a+n+1,cmp);

    int last=-1,ans=0;
    for(int i=1;i<=n;i++)
    {
        if(a[i].l>=last)
        {
            ans++;
            last=a[i].r;
        }
    }

    cout<<ans<<'\n';
    return 0;
}
```

#define int long long
using namespace std;

// 教学输入：n，然后 n 个正整数频次，1<=n<=1000。

    {
        cin>>w[i];

## P3817 小 A 的糖果

[洛谷原题](https://www.luogu.com.cn/problem/P3817)

### 概念与策略

从左到右维护相邻盒子之和不超过x，只删除必要数量。

### 原理与正确性

先把a[1]压到x以内。处理i时至少要删除相邻超出的 d=a[i-1]+a[i]-x。优先从右盒a[i]删：删除左盒与右盒都能修复当前约束，但删右盒还能给下一对留下空间，不会伤害已处理的前缀；在最优解中把相应删除移到右侧不增加删除总数，因此安全。

### 先用一个小例子走一遍

把检查相邻盒子想成拉拉链：从左向右一格一格合好，已经合上的左半边尽量不再打扰。

取 x=3、盒子为4、2、3：先从首盒吃1颗，变成3、2、3；检查前两盒还多2颗，于是从第二盒吃2颗，变成3、0、3；再看后两盒，0+3刚好合格，不用再吃。

```text
4  2  3  →  3  2  3  →  3  0  3
  先删1           再删2        全部合格
```

这里最值得理解的是“为什么动右盒”：下一次检查的是第二盒和第三盒，第二盒变少，相当于提前帮下一步腾了地方。先处理首盒过大的情况，则能保证后面每次需要吃的数量都不超过右盒现有数量。

### 完整 C++17 实现

```cpp
#include <bits/stdc++.h>
#define int long long
using namespace std;

int a[100005];
signed main()
{
    int n,x,ans=0;
    cin>>n>>x;
    for(int i=1;i<=n;i++) cin>>a[i];
    if(a[1]>x)
    {
        ans=a[1]-x;
        a[1]=x;
    }
    for(int i=2;i<=n;i++)
    {
        int d=max(0LL,a[i-1]+a[i]-x);
        a[i]-=d;
        ans+=d;
    }
    cout<<ans<<'\n';
    return 0;
}
```

### 作用、使用场景与易错点

适合相邻上界、前缀已固定的局部修复。a[1]先压到x，保证后续d不会大于a[i]，不会减出负数；答案可能超过32位。例x=3，盒子4,2,3，先删首盒1，再删第二盒2，总3。时间O(n)，空间O(n)。

## P1106 删数问题

[洛谷原题](https://www.luogu.com.cn/problem/P1106)

### 概念与策略

保留原顺序删除k位，使剩余整数最小。优先删掉首个大于后一位的数字。

### 原理与正确性

在所有剩余长度相同的数串中，首个不同位决定大小。若出现相邻下降a>b，删a能让更小的b尽早到高位，比删后面的位更优；重复这一步。若整串非降，就从末尾删，保留较小前缀。本题仅250位，采用直观O(kL)版本。

### 先用一个小例子走一遍

大整数看起来吓人，这题先把它当一排写着数字的卡片。你只能拿走卡片，不能把卡片换位置。结果的高位越小越好，所以先找最左边那个“挡着更小数字”的大数字。

```text
178543  删8 → 17543
17543   删7 → 1543
1543    删5 → 143
143     删4 → 13
```

如果卡片已经是1、2、3、4这样一路不降，前面再也找不到可改善的下降处，就拿走末尾4。删完再处理前导零：1000拿走1以后，三张0卡片表示的整数仍然只是0。

### 完整 C++17 实现

```cpp
#include <bits/stdc++.h>
#define int long long
using namespace std;

signed main()
{
    string s;
    int k;
    cin>>s>>k;
    while(k--)
    {
        int pos=0;
        while(pos+1<(int)s.size()&&s[pos]<=s[pos+1]) pos++;
        s.erase(pos,1);
    }
    int pos=0;
    while(pos<(int)s.size()&&s[pos]=='0') pos++;
    if(pos==(int)s.size()) cout<<0;
    else cout<<s.substr(pos);
    cout<<'\n';
    return 0;
}
```

### 作用、使用场景与易错点

字符串高位优先贪心。例178543删4位得13；1000删1位得0。erase删一位，不能转long long导致溢出。此版本O(kL)、空间O(L)；大规模可用单调栈O(L)，本题不必为短代码引入复杂结构。

## P1478 陶陶摘苹果（升级版）

[洛谷原题](https://www.luogu.com.cn/problem/P1478)

### 概念与策略

先过滤够不到的苹果，再按力气成本升序购买“每件收益都是1”的物品。

### 原理与正确性

同样摘k个苹果，最便宜k个的总力气不大于任意其他k个。交换掉更贵的已选苹果，不减少数量且不会增加力气，因此成本升序最优。可达性必须先判断，不能把够不到但便宜的苹果算进去。

### 先用一个小例子走一遍

先站在树下看一圈：够不到的苹果，无论多省力都不能算候选。把能摸到的苹果摘取成本记为1、2、3、5，剩余力气为8。

先花1，再花2，再花3，摘到3个，剩2点力气。接下来的5点付不起，就可以停了；后面只会更贵。如果先摘5点的，虽然也“摘到了一个”，却挤掉了本来能用相同力气摘到的更多苹果。

这题的收益全是“一个苹果”，因此只需比较成本；别把“低成本优先”误套到每个苹果价值都不同的题。高度判断负责“能不能选”，排序负责“先选哪个”，两个步骤不要混在一起。

### 完整 C++17 实现

```cpp
#include <bits/stdc++.h>
#define int long long
using namespace std;

int cost[5005];
signed main()
{
    int n,s,a,b,cnt=0;
    cin>>n>>s>>a>>b;
    for(int i=1;i<=n;i++)
    {
        int x,y;
        cin>>x>>y;
        if(x<=a+b) cost[++cnt]=y;
    }
    sort(cost+1,cost+cnt+1);
    int ans=0;
    for(int i=1;i<=cnt;i++)
    {
        if(cost[i]>s) break;
        s-=cost[i];
        ans++;
    }
    cout<<ans<<'\n';
    return 0;
}
```

### 作用、使用场景与易错点

适合相同收益下最大化数量；收益不同就不能只按成本排序。高度等于a+b可以摘，力气刚好用完也可以。时间O(n log n)，空间O(n)。

## P5019 铺设道路

[洛谷原题](https://www.luogu.com.cn/problem/P5019)

### 概念与策略

把深度直方图看成由若干条连续水平线段叠成，每次施工对应减去一条线段。

### 原理与正确性

左端需要d[1]层；扫描到i时，若d[i]>d[i-1]，左边已有线段最多延伸d[i-1]层，至少新开差值条。若下降，只需结束若干条，无需新开。这既给出不可突破的下界，又能按水平线段达到它，所以答案Σmax(0,d[i]-d[i-1])，d[0]=0。

### 先用一个小例子走一遍

把凹坑画成积木柱，深度是2、3、1、2。每条横着铺下的施工带，可以连续覆盖相邻的若干格。

```text
第3层      ■
第2层  ■   ■       ■
第1层  ■   ■   ■   ■
位置   1   2   3   4
```

从左往右数“必须新开多少条带子”：位置1需要先开2条；位置2比左边高1，需要再开1条；位置3变矮，只结束多余的带子；位置4又升高1，再开1条。总共2+1+0+1=4。

所以程序不需要真的画这些带子，更不用模拟每一天。`last`只记左边柱子的高度，正差值恰好就是新增带子数。

### 完整 C++17 实现

```cpp
#include <bits/stdc++.h>
#define int long long
using namespace std;

signed main()
{
    int n,last=0,ans=0;
    cin>>n;
    for(int i=1;i<=n;i++)
    {
        int x;
        cin>>x;
        if(x>last) ans+=x-last;
        last=x;
    }
    cout<<ans<<'\n';
    return 0;
}
```

### 作用、使用场景与易错点

差分、区间加减与构造下界。例2,3,1,2贡献2+1+0+1=4，零深度把水平段截断。不要加绝对差，也不用一天一天模拟。时间O(n)，额外空间O(1)。

## P1208 混合牛奶

[洛谷原题](https://www.luogu.com.cn/problem/P1208)

### 概念与策略

有限供应下按单价升序采购，直到需求满足。

### 原理与正确性

若买了贵奶而便宜供应还有剩余，可等量交换，每单位费用下降且需求不变；故存在便宜先买的最优解。供应按整数单位买，本题每单位相同且可买部分产量，不是0/1背包。

### 先用一个小例子走一遍

你要买5单位牛奶：甲每单位2元、最多卖3单位；乙每单位4元、最多卖10单位。

先在甲家买3，花6元；还缺2，再向乙买2，花8元，总共14元。不是每家都要买，也不是选中乙就必须把他的10单位全买走。

代码中的 `need` 是购物清单上还差的数量，`buy=min(need,a[i].a)` 就是“缺多少买多少，但不能超过这家现有库存”。把牛奶换成相同规格的原料，逻辑也一样；如果不同来源有质量差别，就不再是这个简单模型。

### 完整 C++17 实现

```cpp
#include <bits/stdc++.h>
#define int long long
using namespace std;

struct node
{
    int p,a;
}a[5005];
bool cmp(node x,node y)
{
    return x.p<y.p;
}
signed main()
{
    int need,m,ans=0;
    cin>>need>>m;
    for(int i=1;i<=m;i++) cin>>a[i].p>>a[i].a;
    sort(a+1,a+m+1,cmp);
    for(int i=1;i<=m&&need>0;i++)
    {
        int buy=min(need,a[i].a);
        ans+=buy*a[i].p;
        need-=buy;
    }
    cout<<ans<<'\n';
    return 0;
}
```

### 作用、使用场景与易错点

适合货物同质、供应有限、单位价格固定的采购；不同质量或运费门槛需重新证明。需求可以为0，供应总量按题意保证足够。时间O(m log m)，空间O(m)。

## P1094 纪念品分组

[洛谷原题](https://www.luogu.com.cn/problem/P1094)

### 概念与策略

排序后用双指针，每次为最重物品决定单独一组或与最轻者配对。

### 原理与正确性

若最轻+最重仍超上限，最重与任何人都不能同组，必须单独。否则可让最重与最轻配对：若原解二者各与别人配对，把它们换成一对，剩余两件也能成对，因为最重不小于它们，新的剩余对不会超出原来与最重配对的和；有单独者时交换也不增加组数。

### 先用一个小例子走一遍

把纪念品按价格摆成一排5、8、12、18，上限20。两端指针像两只手：右手每次拿走最重的；左手只在它能顺便带走最轻的时向右移。

```text
5  8  12  18   最轻5也配不了18 → 18单独
5  8  12       5+12<=20       → 5与12一组
   8           只剩一件        → 8单独
```

共3组。不要一看到超限就移动左指针，把最轻物品丢掉；当前要安置的是最重物品，无法配对时应该让它独自成组。每组最多两件，是这个双指针方法能够成立的关键限制。

### 完整 C++17 实现

```cpp
#include <bits/stdc++.h>
#define int long long
using namespace std;

int a[30005];
signed main()
{
    int w,n;
    cin>>w>>n;
    for(int i=1;i<=n;i++) cin>>a[i];
    sort(a+1,a+n+1);
    int l=1,r=n,ans=0;
    while(l<=r)
    {
        if(l<r&&a[l]+a[r]<=w) l++;
        r--;
        ans++;
    }
    cout<<ans<<'\n';
    return 0;
}
```

### 作用、使用场景与易错点

仅适用于每组最多两件。若最多三件，双指针策略不能原样套用。l==r只剩一件算一组。时间O(n log n)，空间O(n)。

## P4995 跳跳！

[洛谷原题](https://www.luogu.com.cn/problem/P4995)

### 概念与策略

从地面0出发，交替跳剩余最高、最低石头，让大高度差反复出现，目标是最大平方差和。

### 原理与正确性

关键不是“选择最近”，而是让路径高低交错。对a<=b<=c<=d有(d-a)^2+(c-b)^2-[(c-a)^2+(d-b)^2]=2(d-c)(b-a)>=0，说明把高低端交错配对不会降低收益；对路径可通过交换并反转中间子段保持内部边代价，将端点逐步整理为高低交替。地面是全局最低且固定起点，规范最优顺序可取最大、最小、次大、次小……。这一性质依赖平方距离和正高度，不是任意代价函数通用的“最远优先”。

### 先用一个小例子走一遍

这只青蛙不是想省力，而是想让体力花得最多。先把题目的“最大”圈出来，否则很容易朝相反方向做。

三个石头高1、2、3：平平稳稳地0→1→2→3，只花1+1+1=3；上下折腾地0→3→1→2，却花9+4+1=14。

```text
高度3     ●
          ↑ ╲
高度2     │   ╲   ●
高度1     │     ● ↗
地面0     ●
顺序      地面 → 最高 → 最低 → 次高
```

程序中的 `high` 就是一张翻来翻去的提示牌：“这次拿右端最高”“下次拿左端最低”。注意最后停在某块石头上，不要额外加一次回到地面的费用。下面的四点不等式解释了高低交错为何有利；不能只记“每次跳最远”就把它推广到其他代价函数。

### 完整 C++17 实现

```cpp
#include <bits/stdc++.h>
#define int long long
using namespace std;

int a[305];
signed main()
{
    int n;
    cin>>n;
    for(int i=1;i<=n;i++) cin>>a[i];
    sort(a+1,a+n+1);
    int l=1,r=n,now=0,ans=0;
    bool high=true;
    while(l<=r)
    {
        int x;
        if(high) x=a[r--];
        else x=a[l++];
        ans+=(x-now)*(x-now);
        now=x;
        high=!high;
    }
    cout<<ans<<'\n';
    return 0;
}
```

### 作用、使用场景与易错点

极值交替、凸距离最大化的经典模型。例1,2,3：0→3→1→2得9+4+1=14；只升序得1+1+1=3。不能中途回地面，也不用最后回0。答案用64位。时间O(n log n)，空间O(n)，测试用全排列验证小规模。

## P4447 分组

[洛谷原题](https://www.luogu.com.cn/problem/P4447)

### 概念与策略

排序后将实力x接到末尾为x-1的组中；若可接多个，优先延长其中最短的组。目标是最大化最小组大小。

### 原理与正确性

同一末尾的组有相同未来可接实力，区别只是已有长度。把当前和未来可用延长机会优先分给短组，可以避免短组过早停下成为瓶颈；若一个方案把后续延长给了长组，却让短组停下，可交换这两组后续后缀，连续性不变且最小长度不减。无可接组才新建。用每个末尾值对应的小根堆保存组长。

### 先用一个小例子走一遍

这题不是“尽量少分几组”，而是关心最小的那组能不能变大。看实力1、2、2、3：

| 读到的实力 | 当前分组 | 原因 |
|---|---|---|
| 1 | [1] | 没有以0结尾的组，只能新开 |
| 第一个2 | [1,2] | 接在1后面 |
| 第二个2 | [1,2]、[2] | 同一组不能出现两个2 |
| 3 | [1,2]、[2,3] | 两组都能接3，先救短的[2] |

如果最后把3给长组，就得到[1,2,3]和[2]，最小组只有1人。给短组后最小组有2人，这才改善了题目真正关心的瓶颈。

`q[x-1]`可以读成“所有以x-1结尾的组组成的候选池”，堆里存的是组长，顶部是最短组。你不是在给所有组排序，只是在当前能接上的候选里挑最需要延长的那个。

### 完整 C++17 实现

```cpp
#include <bits/stdc++.h>
#define int long long
using namespace std;

int a[100005];
map<int,priority_queue<int,vector<int>,greater<int>>> q;
signed main()
{
    int n;
    cin>>n;
    for(int i=1;i<=n;i++) cin>>a[i];
    sort(a+1,a+n+1);
    for(int i=1;i<=n;i++)
    {
        int x=a[i],len=0;
        if(!q[x-1].empty())
        {
            len=q[x-1].top();
            q[x-1].pop();
        }
        q[x].push(len+1);
    }
    int ans=n;
    for(auto &item:q)
    {
        if(!item.second.empty()) ans=min(ans,item.second.top());
    }
    cout<<ans<<'\n';
    return 0;
}
```

### 作用、使用场景与易错点

此题的map按实力值查组，priority_queue的top取最短组；auto &item只用于遍历每个“末尾值→小根堆”映射。重复实力不能放同组，负实力不能直接作为数组下标。例1,2,2,3形成两组[1,2]与[2,3]，最小长度2。时间O(n log n)，空间O(n)。

## P1080 国王游戏

[洛谷原题](https://www.luogu.com.cn/problem/P1080)

### 概念与策略

按每位大臣左右手乘积a×b升序排序；维护前面所有左手数乘积，先除当前右手计算奖赏，再乘当前左手。乘积需要高精度。

### 原理与正确性

设当前前缀积P，相邻i,j的乘积满足ai*bi<=aj*bj。顺序i,j的两项为floor(P/bi)、floor(P*ai/bj)；反序j,i包含floor(P*aj/bi)。因为aj>=1，前一项不大于该值；由乘积排序关系，后一项也不大于该值。故正序最大值不大于反序最大值，其他大臣前缀积不变，交换安全。重复消逆序即得结论。

### 先用一个小例子走一遍

先不要被高精度吓住，把这题分成两层：先想清大臣怎么排，再处理乘积太大怎么存。

国王左手为2，三个大臣为A=(2,3)、B=(3,4)、C=(4,2)。括号是左手、右手，排序依据是两数乘积，分别6、12、8，所以顺序为A、C、B。

| 当前大臣 | 前面左手乘积P | 本人奖赏floor(P/右手) | 接着把P乘什么 |
|---|---:|---:|---:|
| A=(2,3) | 2 | 0 | 乘2，变4 |
| C=(4,2) | 4 | 2 | 乘4，变16 |
| B=(3,4) | 16 | 4 | 乘3，变48 |

本轮最大值为4。如果只按左手从小到大排成A、B、C，奖赏变成0、1、6，反而更差。

代码的 `num` 像一个很多格的算盘：个位放num[1]，十位放num[2]。乘法从低位往高位进位，除法却从高位往低位处理余数。`check`只读当前前缀积来算奖赏，`mul`才把当前大臣加入前缀；交换这两步就把他自己的左手错误地算进奖赏了。

### 完整 C++17 实现

```cpp
#include <bits/stdc++.h>
#define int long long
using namespace std;

struct node
{
    int a,b;
}a[1005];
int num[5005],tmp[5005],best[5005];
int len=1,blen=1;
bool cmp(node x,node y)
{
    return x.a*x.b<y.a*y.b;
}
void mul(int x)
{
    int carry=0;
    for(int i=1;i<=len;i++)
    {
        int v=num[i]*x+carry;
        num[i]=v%10;
        carry=v/10;
    }
    while(carry)
    {
        num[++len]=carry%10;
        carry/=10;
    }
}
void check(int x)
{
    int rem=0;
    for(int i=len;i>=1;i--)
    {
        rem=rem*10+num[i];
        tmp[i]=rem/x;
        rem%=x;
    }
    int tlen=len;
    while(tlen>1&&tmp[tlen]==0) tlen--;
    bool larger=tlen>blen;
    if(tlen==blen)
    {
        for(int i=tlen;i>=1;i--)
        {
            if(tmp[i]!=best[i])
            {
                larger=tmp[i]>best[i];
                break;
            }
        }
    }
    if(larger)
    {
        blen=tlen;
        for(int i=1;i<=blen;i++) best[i]=tmp[i];
    }
}
signed main()
{
    int n,king,right;
    cin>>n>>king>>right;
    for(int i=1;i<=n;i++) cin>>a[i].a>>a[i].b;
    sort(a+1,a+n+1,cmp);
    num[1]=1;
    mul(king);
    for(int i=1;i<=n;i++)
    {
        check(a[i].b);
        mul(a[i].a);
    }
    for(int i=blen;i>=1;i--) cout<<best[i];
    cout<<'\n';
    return 0;
}
```

### 作用、使用场景与易错点

排序交换与高精度组合。num倒序存十进制数字，mul为高精度乘小整数，check从高位长除法得到商并按长度/高位比较最大值。国王始终最前面，他的右手不影响答案；先乘再除会错。最多1001个小于10000的因子，不超过4004位，5005位安全。时间O(n log n+nD)，空间O(n+D)。不能因为#define int long long就省掉高精度。

## P1012 拼数

[洛谷原题](https://www.luogu.com.cn/problem/P1012)

### 概念与策略

比较两个字符串x+y和y+x，较大的排列方式排前面，不能按原数值大小排序。

### 原理与正确性

相邻交换只改变拼接中这两个块；前后内容相同，两种局部拼接长度也相同，因此x+y较大时放x在前不会变差。比较器等价于比较无限周期串的顺序（或x/(10^len(x)-1)），所以具有一致性，能够用于sort；相等时返回false。

### 先用一个小例子走一遍

把数字写成不能拆开的积木块。9和34谁先放？别问哪个整数大，直接把两种拼法写出来：934和349，显然9应该在前。

再看容易看错的12与121：

```text
12在前：12 | 121 → 12121
121在前：121 | 12 → 12112
                    ↑ 第四位才分出大小
```

因此比较器返回 `x+y>y+x`。它比较的是两个完整拼接结果，既不是只看第一位，也不是短的永远在前。所有块排好后直接逐块输出即可，没必要把长长的结果真的转成一个整数。

### 完整 C++17 实现

```cpp
#include <bits/stdc++.h>
#define int long long
using namespace std;

string a[25];
bool cmp(string x,string y)
{
    return x+y>y+x;
}
signed main()
{
    int n;
    cin>>n;
    for(int i=1;i<=n;i++) cin>>a[i];
    sort(a+1,a+n+1,cmp);
    for(int i=1;i<=n;i++) cout<<a[i];
    cout<<'\n';
    return 0;
}
```

### 作用、使用场景与易错点

适用于把完整数字块排列成最大拼接数。例9与34：934>349，所以9在前；12与121：12121>12112，所以12在前。结果用字符串输出，不做整数转换。若单块最大长度L，时间O(n log n×L)，存储O(nL)。
